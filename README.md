# 中小农户智能财务管理系统 · 乡村财务智管家

> 项目代号：乡村财务智管家 ｜ 暨南大学 网络空间安全学院
> 状态：**可运行的本地产品**（模型层除外）｜ 零第三方依赖 ｜ 断网可用

---

## 一句话

部署在村集体办公电脑、断网可用、把农户的经营流水变成**银行能核验**的财务报表。

## 现在能做什么

不是 PPT，是能跑的东西：

| 能力 | 入口 | 状态 |
|---|---|---|
| 手动记账（卡片表单、单位/地块/票据照片） | `/entry` | 可用 |
| 一句话记账（规则抽取日期/金额/科目/数量） | `/quick` | 可用 |
| 账本、待确认草稿、作废 | `/ledger`、`/drafts` | 可用 |
| 年度核算：显性/隐性成本、保本价、敏感性区间 | `/summary` | 可用 |
| T1 信贷尽调 / T2 财政补贴 / T3 备案报表 | `/reports` | 可用 |
| 导出：HTML 打印稿、Excel（.xlsx）、银行材料包（.zip） | `/reports` | 可用 |
| 快照签章（SM2-with-SM3）与离线验证 | `/verify`、`tools/verify_snapshot.py` | 可用 |
| 审计哈希链（SM3，防改防删） | `/admin/audit` | 可用 |
| 隐私分级、掩码、代币化、受控外发与复检 | `/privacy` | 可用 |
| 农户档案、地块、参数包、规则包、账号、备份、自检 | `/admin` | 可用 |
| 票据拍照**自动识别**金额 | — | **未安装**（模型层不在本期） |
| 语音**自动**转写记账 | — | **未安装**（模型层不在本期） |
| 语音播报确认 | 记账后 | 依赖浏览器自带语音，不可用时静默降级 |

界面会把"缺什么"直接说出来，不做静默降级——这是设计原则，不是提示文案。

## 快速开始

### 村委电脑（Windows，推荐）

1. 安装 Python 3.11+（安装时勾选 **Add Python to PATH**）；
2. 把整个目录拷到电脑上（绿色部署，无安装程序、无管理员权限、不写注册表）；
3. 双击 **`启动.bat`**：
   - 第一次会自动进入建账流程（村名、区域代码、管理员口令）；
   - 之后每次直接启动，浏览器自动打开 `http://127.0.0.1:8765/`。

关闭黑窗口 = 停止服务，账目不会丢。

### 命令行（开发/答辩机）

```bash
python -m app.cli init --village 新围村 --region 4401xx --admin admin
python -m app.cli demo --village 新围村 --year 2026   # 写入一套演示账本
python -m app.cli serve                               # 启动
```

`--data` 可指定数据目录（默认 `./data`）。Linux/macOS 用 `./start.sh`。

### 只想看核算内核

```bash
python demo.py     # 账本 → 核算 → 报表 → 快照 → 重放 → 审计链
python -m unittest discover -s . -p "test_*.py" -t .   # 159 项测试
```

`python demo.py` 的真实输出（非示意）：

```text
经营面积      10 亩（自有 8 / 租入 2）
经营收入         13,520.00 元
补贴收入            300.00 元（单列）
现金成本          6,900.00 元
推算成本          6,891.35 元（土地机会 6,400.00 + 折旧 17.10 + 自用工 474.25）
总成本           13,791.35 元
净收益               28.65 元（亩均 2.87 元）
保本价        地头 2.52 元 / 到场 2.59 元（每公斤）
--------------------------------------------------------------------
重放校验      通过（逐分一致）
篡改检出      是（改 1 元即被重放发现）
审计链        9 条，校验通过
最敏感因素    price（净收益区间 -4,526.30 ~ 5,665.20 元）
```

这组数字本身就是最有力的论据：**10 亩水稻按 2.6 元/公斤卖完，扣掉被长期忽略的土地机会成本与自用工之后，全年净收益 28.65 元——保本价 2.59，实际售价 2.60。** 农户"觉得赚了其实没赚"，正是因为隐性成本从未被算过。

## 架构

```text
web（本地 HTTP，服务端渲染）
  └─ 领域服务：ledger / privacy / report / snapshot / verify / audit / selfcheck
       └─ core（确定性核算内核，纯函数）
            └─ SQLite（事件溯源，金额整数分）
```

依赖方向是单向的：`core` 不认识数据库、HTTP、密钥；模型层即使整块缺失，核算与报表照样能跑。

```text
app/
├── config.py / db.py / schema.sql   # 配置、SQLite（WAL）、表结构
├── repo.py                          # 仓储（只取存，不含业务判断）
├── calc.py                          # 数据库 → 核算内核适配
├── ledger.py                        # 记账状态机、去重、金额校验
├── extract.py                       # 一句话记账的规则抽取（无模型）
├── privacy.py / privacy_svc.py      # L1/L2/L3、掩码、代币、外发复检
├── evidence.py                      # 凭证加密归档与哈希校验
├── keys.py / signing.py             # KEK/DEK、SM2 签章密钥
├── report.py / report_svc.py / xlsx.py  # T1/T2/T3、HTML、XLSX、材料包
├── snapshot_svc.py / verify.py      # 快照、重放、离线验证
├── audit_svc.py / selfcheck.py      # 审计链持久化、自检
├── backup.py                        # 一致性备份（可选口令加密）
├── cli.py                           # init / serve / demo / backup / verify / export …
└── web/                             # 路由、会话、CSRF、页面、静态资源

core/
├── money.py / models.py / costing.py / reports.py / snapshot.py / audit.py
├── crypto/  sm3.py  sm4.py  sm2.py   # 国密，纯标准库
└── tests/                            # 内核测试

tools/verify_snapshot.py              # 银行侧单文件离线验签工具
```

## 几个关键设计（以及为什么）

| 选择 | 理由 |
|---|---|
| **AI 只做抽取，不做计算** | 模型出的数字不可审计，银行不会采信；数字必须由确定性引擎产生 |
| **不存结果账，只存事件** | 改一笔账不需要"反结账"；任意数字可追到来源 |
| **显性/隐性成本分列** | 银行看现金流，农户看真实成本，合并会同时误导两边 |
| **快照自带输入** | 一年后农户补记/作废了账，旧快照仍能逐分重放——否则无法区分"被篡改"与"正常调整" |
| **国密自己实现** | 交付环境装不了包；SM3/SM4/SM2 均已用国标向量与 OpenSSL/PyCryptodome 交叉验证 |
| **金额整数分、全链路定点** | 浮点在报表上会"差一分"，而银行恰恰抽查那一分 |
| **零第三方依赖** | 村委电脑装不上包，也不该为跑一个记账系统装一套运行时 |
| **不做区块链** | 单村单机不需要分布式共识，哈希链 + 签章够用且可解释 |

## 诚实清单

**已实现并测试（159 项自动化测试）**

- 事件溯源数据模型、记账状态机、重复记账拦截
- 确定性核算：显性/隐性成本、自用工 α、土地机会成本、农机折旧（含封顶）、保本价两口径、盈亏平衡、三因素敏感性
- 快照：事件集哈希、Merkle 根、SM2 签章、逐项重放；篡改必被发现
- 审计哈希链（SM3）：改/删/改时间戳均可检出
- 国密：SM3（OpenSSL 逐例比对）、SM4-GCM（PyCryptodome AES-GCM 比对）、SM2（国标示例向量 + gmssl 双向互验）
- 隐私：身份证/银行卡/手机号校验位、L1 掩码、代币化、外发白名单与解压后复检
- 报表：T1/T2/T3、HTML 打印版、XLSX（LibreOffice 校验通过）、银行材料包
- 本地 Web：登录限速、会话、CSRF、角色权限、老年友好字号与点击区
- 运维：一键备份/恢复（可口令加密）、系统自检、命令行全套

**未实现（明确边界，不含糊）**

| 项 | 原因 | 替代路径 |
|---|---|---|
| OCR / ASR / 小模型 | 本期范围就是"除模型外" | 手填、一句话打字、票据拍照归档；接口与界面已预留并显式标注 |
| 服务端 PDF 生成 | 零依赖环境下嵌中文字体不现实 | 打印优化 HTML + 浏览器「另存为 PDF」；Excel 同步可导出 |
| 纸质报表二维码 | 需要 QR 编码器与内网查验页 | 报表脚注打印快照哈希前 32 位，可人工核对 |
| SM2 UKey 硬件签章 | 依赖具体 UKey 驱动 | 软件密钥 + 设备标识，密钥文件可加口令保护 |
| 对公模板与银行联调 | 依赖外部机构 | T1/T2/T3 结构已按尽调清单设计，字段可逐项溯源，等机构确认后改版本号 |
| 传感器 / 遥感产量 | 首版不做（V2 §1.3） | 面积 × 县域单产基准区间估算 |

**与技术方案的偏差（答辩时会被问，先说清楚）**

| 方案写的 | 实际做的 | 原因 |
|---|---|---|
| FastAPI + Uvicorn | 标准库 `http.server` 极简框架 | 断网装不了包；单村单机并发极低 |
| Argon2id | scrypt（内存硬） | 标准库无 Argon2；scrypt 同样抗离线爆破 |
| HTML→PDF 服务端渲染 | 打印优化 HTML + 浏览器打印 | 见上 |
| 报表二维码 | 哈希文本 | 见上 |

## 常见问题（技术）

**Q：为什么不用现成的国密库？**
A：交付环境断网且无管理员权限。SM3/SM4/SM2 都已按国标实现，并用官方测试向量 + OpenSSL / PyCryptodome / gmssl 交叉验证；代码约 700 行，可被独立审阅。

**Q：SQLite 单机能撑住吗？**
A：一个村一年几千到几万条事件，报告生成毫秒到百毫秒级；WAL + 每请求独立连接足够。真实瓶颈是人的录入速度，不是数据库。

**Q：数据被拷走怎么办？**
A：凭证文件与姓名/手机号用 SM4-GCM 加密，密钥在 `data/keys/`。只拷数据库解不开内容。**但**能物理接触这台电脑并拿到整个 `data/` 的人可以解密——这一层防的是"拷走数据库"和"U 盘丢失"，不是防"坐在电脑前的人"。要更强，可给设备密钥加口令（`python -m app.cli protect-keys`）。

**Q：怎么证明报表是真的？**
A：快照里带事件集哈希、Merkle 根、SM2 签名与公钥。银行用 `tools/verify_snapshot.py` 离线验签即可。它能证明"账本未被事后修改、报表忠实于账本、有人对它负责"，**不能**证明"农户没有造假账"——后者靠抽验原始票据与交叉核对。

## 与 V1 申报材料的关系

V1 的两份材料在技术描述上有 6 处会被现场击穿的硬伤，其中最危险的两条：

1. **把 Mask-BERT 当作手写文字识别模型** —— Mask-BERT 不处理图像，这条一旦被追问即失分；
2. **"已获农业农村部试点认可""已通过农村试点验证"** —— 无法出示证明，且与"乙类：未创业"自相矛盾。

逐条问题与替换句见 [V1诊断与修订对照.md](docs/V1诊断与修订对照.md) 与 [对外表述口径与答辩要点.md](docs/对外表述口径与答辩要点.md)。
