# 中小农户智能财务管理系统 · 技术方案 V2

> 项目代号：乡村财务智管家 ｜ 暨南大学 网络空间安全学院
> 本仓库是**技术方案与核算内核参考实现**，不是可交付的完整产品。

---

## 一句话

部署在村集体办公电脑、断网可用、把农户的经营流水变成**银行能核验**的财务报表。

## 这套方案要解决的真问题

农户"记不清账、算不清本、卖不准价、贷不到款"。而现有方案绕不过一个死结：

> 银行要信数据，就要看原始凭证；农户要安全感，就要求数据不出村。

V2 的答案不是"脱敏后上传"，而是 **把"数据外发"换成"证明外发"**：

| 要证明的事 | 机制 |
|---|---|
| 报表忠实于账本 | 核算引擎是纯函数，同一输入必然同一输出，可逐分重放 |
| 账本未被事后修改 | 事件集 Merkle 根 + 哈希链审计日志 |
| 有人对报表负责 | 村委签章（SM2）+ 设备标识，绑定到具体快照 |
| 原始数据不出村 | L1 直接标识在数据模型里就没有通往报表的路径 |

## 参考实现（`core/`）

约 850 行（含中文注释）、纯标准库、无第三方依赖。它证明的不是"我能写代码"，而是三句技术主张：

```bash
# 跑一遍端到端：账本 → 核算 → 报表 → 快照 → 重放 → 审计链
python demo.py

# 37 个单元测试（确定性、折旧封顶、保本价口径、篡改检出…）
python -m unittest discover -s core/tests -t . -v
```

`python demo.py` 的输出（真实运行结果，非示意）：

```text
经营面积      10 亩（自有 8 / 租入 2）
经营收入         13,520.00 元
补贴收入            300.00 元（单列）
现金成本          6,900.00 元
推算成本          6,891.35 元（土地机会 6,400.00 + 折旧 17.10 + 自用工 474.25）
总成本           13,791.35 元
净收益               28.65 元（亩均 2.87 元）
保本价        地头 2.52 元 / 到场 2.59 元（每公斤）
--------------------------------------------------------------------
重放校验      通过（逐分一致）
篡改检出      是（改 1 元即被重放发现）
审计链        9 条，校验通过
最敏感因素    price（净收益区间 -4,526.30 ~ 5,665.20 元）
```

这组数字本身就是项目最有力的论据：**10 亩水稻按市场价 2.6 元/公斤卖完，扣掉被长期忽略的土地机会成本与自用工之后，全年净收益 28.65 元——保本价 2.59，实际售价 2.60。** 农户"觉得赚了其实没赚"，正是因为隐性成本从未被算过。

产出物见 [`samples/`](samples/)：

- `示例账本.jsonl` — 8 条事件（含 1 条草稿，演示"草稿不入账"）
- `示例快照.json` — 事件集哈希 + Merkle 根 + 签章载荷
- `示例报表.md` — 一页摘要 + 成本结构 + T1 信贷尽调版 + 敏感性区间

## 关键设计选择（以及为什么）

| 选择 | 理由 |
|---|---|
| **AI 只做抽取，不做计算** | 模型出的数字不可审计，银行不会采信；数字必须由确定性引擎产生 |
| **不存结果账，只存事件** | 改一笔账不需要"反结账"；任意数字可追到来源；规则升级不污染历史报表 |
| **显性/隐性成本分列** | 银行看现金流，农户看真实成本，合并会同时误导两边 |
| **保本价给两个口径** | 地头价 vs 到场价，是农户真实的两个谈判场景 |
| **敏感性给区间不给点值** | α 取 0.6 还是 0.8，结论可能从"赚"变"亏"；假精确比不给更危险 |
| **不做区块链** | 单村单机不需要分布式共识，哈希链 + 签章够用且可解释 |
| **不接传感器与作物图像** | 村委办公室没有田间设备；首版承诺做不到的事，是答辩自伤 |
| **离线是默认态** | 涉农场景网络不可靠；"联网才能用"等于不可用 |

## 已完成 / 未完成（诚实清单）

**已完成（可现场演示）**

- 事件溯源数据模型与校验
- 确定性核算引擎：显性成本、自用工折算（α）、自有土地机会成本、农机折旧（工作量法/年数总和法，含封顶）
- 保本价（地头/到场两口径）、盈亏平衡产量、三因素敏感性区间
- 事件集哈希、Merkle 根、快照签章载荷、重放校验（改 1 分即被发现）
- 审计日志哈希链（改/删任一条即被检出）
- 37 个单元测试全绿

**未完成（有里程碑，见主文档 §12）**

- OCR / ASR 接入与字段抽取（M3）
- 隐私分级、脱敏、外发复检（M4）
- 老年友好界面与语音播报（M5）
- 试点村部署与可用性实测（M6）
- SM2 实际签章（依赖 UKey/密钥文件，部署环节）
- T2/T3 报表模板与银行/补贴部门确认（M7）

**生产与参考实现的差异**

| 项 | 参考实现 | 生产实现 |
|---|---|---|
| 摘要算法 | SHA-256 | SM3（GB/T 32905），接口不变 |
| 加密 | 未实现 | SM4-GCM + KEK/DEK 两级密钥 |
| 签章 | 只产出待签载荷 | SM2 签名（村委 UKey + 设备标识） |
| 存储 | 内存对象 | SQLite（WAL）+ 加密文件库 |
| 报表 | Markdown | HTML→PDF（A4，黑白激光可读） |

## 与 V1 申报材料的关系

V1 的两份材料（挑战杯申报表、专项资金申报书）在技术描述上有 6 处会被现场击穿的硬伤，其中最危险的两条：

1. **把 Mask-BERT 当作手写文字识别模型** —— Mask-BERT 不处理图像，这条一旦被追问即失分；
2. **"已获农业农村部试点认可""已通过农村试点验证"** —— 无法出示证明，且与"乙类：未创业"自相矛盾。
