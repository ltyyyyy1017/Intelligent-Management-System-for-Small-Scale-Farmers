# 部署与验证手册

> 面向：到村部署的同学、村委 IT 支持人员、需要核验报表的银行/农经站
> 目标：从一台空电脑到"能出报表、能被验签"，全程不联网、不需要管理员权限

---

## 一、环境要求

| 项 | 最低 | 推荐 |
|---|---|---|
| 操作系统 | Windows 10 64 位 | Windows 10/11 64 位 |
| Python | 3.11 | 3.12 / 3.13 |
| CPU / 内存 | 4 核 / 8 GB | i5-8250U / 8 GB |
| 磁盘 | 20 GB 空闲 | SSD |
| 屏幕 | 1280×720 | 1920×1080 |
| 网络 | **不需要** | 仅村内局域网（可选） |

第三方依赖：**零**。不需要 `pip install`，不需要 Docker，不需要数据库服务。

---

## 二、首次部署（5 分钟）

1. **装 Python**
   到 python.org 下载 3.11+ 的 Windows 安装包，安装时**勾选 Add Python to PATH**。
   装完在命令行执行 `python --version` 能看到版本号即可。

2. **拷目录**
   把整个项目目录拷到村委电脑，例如 `D:\乡村财务智管家\`。
   目录可以放在任何位置，但**不要放在 C:\Program Files**（写入权限问题）。

3. **双击 `启动.bat`**
   第一次会自动进入建账流程：

   ```
   村名：新围村
   区域代码：4401xx
   管理员账号：admin
   管理员口令：（至少 8 位，自己记住）
   ```

   完成后浏览器会自动打开 `http://127.0.0.1:8765/`。

4. **第一次登录后要做的三件事**
   - 管理 → 添加农户（姓名、村组；手机号可不填）
   - 管理 → 添加地块（面积、权属、作物）
   - 管理 → 新建经办人账号（不要把管理员账号给日常记账用）

---

## 三、日常启动 / 停止

- 启动：双击 `启动.bat`，等浏览器自动打开；
- 停止：关闭那个黑色命令行窗口（或按 Ctrl+C）；
- 数据不会因为关闭而丢失；再次双击就继续用。

> 不要同时开两个窗口启动两次：第二个会因端口被占用而失败（见故障排查）。

---

## 四、局域网访问（可选）

默认只允许本机访问（`127.0.0.1`），最安全。如果村委希望用另一台电脑/平板记帐：

```bash
python -m app.cli serve --lan
```

启动时会打印本机局域网地址（如 `http://192.168.1.23:8765/`），同网段设备可访问。
首次可能需要在 Windows 防火墙里允许 Python 的**专用网络**入站。

**红线**：
- 只在村内网使用，**绝不要**做端口映射到公网、不要用内网穿透工具；
- 局域网模式下，任何能连上该网段的人都能看到登录页，账号口令必须逐个设置、不要共用；
- 答辩演示时如无必要，保持默认的本机模式。

## 五、数据目录

所有运行期数据都在 `data/`（可用 `--data` 指定别处）：

| 路径 | 内容 | 能否单独拷走 |
|---|---|---|
| `data/village.db` | 账本、农户、快照、审计链（WAL 模式） | 可拷，但敏感字段是密文 |
| `data/evidence/` | 票据照片等凭证（SM4-GCM 密文） | 单独拷走解不开 |
| `data/keys/` | 设备密钥、数据密钥、签章密钥 | **最敏感**，泄露=全部可解 |
| `data/exports/` | 导出的报表与材料包 | 含 L2/L3，不含 L1 |
| `data/backups/` | 备份文件 | 含密钥 |

## 六、备份与恢复

### 6.1 备份

页面上：管理 → 「立即备份」。
命令行（推荐定期做）：

```bash
python -m app.cli backup --encrypt
```

- 不带 `--encrypt`：生成 `nfm-backup-...-unencrypted.zip`，文件名明确写"未加密"；
- 带 `--encrypt`：生成 `.nfmbak`，用口令加密整个包（scrypt + SM4-GCM）。

**备份含设备密钥**，所以：

- U 盘必须上锁保管，不要和电脑放在同一个抽屉；
- 加密备份的口令另行保管（写在纸上锁好），忘记口令 = 备份作废；
- 建议频率：每周一次 + 每次批量录入后一次。

### 6.2 恢复

```bash
# 恢复到新电脑（先装好项目、但不要启动过）
python -m app.cli restore nfm-backup-20260601-090000.nfmbak
# 按提示输入备份口令；目标目录已有数据时会要求加 --force
```

恢复到新电脑后，设备标识会随 `keys/` 一起恢复，历史快照仍可验签。

### 6.3 给设备密钥加口令（可选，更安全）

```bash
python -m app.cli protect-keys
```

设置后每次启动需要输入该口令（或设置环境变量 `NFM_KEY_PASSPHRASE`）。
这会把"拿到整个 data 目录就能解密"变成"还要知道口令"。

## 七、银行/监管侧验签

### 7.1 材料包里有什么

`/reports` → 「银行材料包」生成一个 zip：

```
S-2026-0001/
├── 报表-T1 信贷尽调版.html    # 可打印/另存 PDF
├── 快照.json                  # 数字指纹：事件集哈希、Merkle 根、SM2 签名、公钥
└── 验证说明.txt               # 三步核验说明与边界声明
```

### 7.2 三步核验

**第 1 步 验签（任何一台电脑都能做，不需要本系统）**

```bash
python tools/verify_snapshot.py 快照.json
```

输出示例：

```
==========================================================
快照验证结果
==========================================================
  SM2 签名      : 有效
  载荷摘要自洽  : 是
  签章人        : 村委-李四
  设备标识      : DEV-21D9193DBE9A212F
  事件条数      : 9
  出表时间      : 2026-10-18T06:15:15+08:00
  Merkle 根     : 9c9c77fd9e21f504...
----------------------------------------------------------
结论：通过
```

**第 2 步 验根（在村委本机）**

在系统里打开 `/verify?sid=S-2026-0001`，会做三件事：

- 用公钥验签；
- 用**快照自带的输入**重算事件集哈希与 Merkle 根；
- 逐项重放核算结果，确认与快照里的输出一致。

**第 3 步 抽验（可选，需农户单次授权）**

银行指定某一笔（如"3 月化肥支出"），村委在本机调出该笔原始凭证（`/admin` → 凭证 or 直接按事件号查），只披露这一笔。

### 7.3 边界（必须同时告知审核人员）

这套机制证明：**账本未被事后修改、报表忠实于账本、有人对报表负责**。
它**不证明**农户没有造假账——防造假靠抽验原始票据与交叉核对，属于业务风控。
任何把"可验证"说成"防造假"的宣传都是错的。

## 八、升级

1. 停服务；
2. 先把旧目录整体备份（含 `data/`）；
3. 用新版本的程序文件覆盖（**不要删 `data/`**）；
4. 启动。首次启动会自动补齐表结构（`schema.sql` 全部 `IF NOT EXISTS`）；
5. 跑一次「管理 → 自检」，确认审计链、密钥、快照重放都通过。

> 历史上出现过表结构变更的版本（例如 `snapshot.inputs_json`），升级前务必先备份。
> 如果自检报"表不存在"，说明需要手工迁移，请联系维护者。

## 九、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 bat 闪一下就没了 | 没装 Python 或没加到 PATH | 命令行执行 `python --version` 验证；重装并勾选 PATH |
| 提示端口被占用 | 已经启动过一个实例 | 关掉旧的黑窗口；或 `serve --port 8766` |
| 页面提示"页面已过期" | CSRF 令牌失效（刷新/多标签） | 刷新页面重试 |
| 登录提示"账号或口令不对" | 口令错 / 账号被停用 | 管理员可在管理页启用；忘记口令用 `reset-password` |
| 提示"数据密钥损坏" | `keys/` 与数据库不匹配 | 用备份恢复；不要只拷 `village.db` |
| 报表打不开/样式乱 | 浏览器过旧 | 用 Edge/Chrome；报告是离线 HTML，不依赖网络 |
| 打印没有"另存为 PDF" | 浏览器不同 | Chrome/Edge 打印对话框里选"另存为 PDF" |
| 自检报"审计链未通过" | 数据被改过 | **立即停用**，备份现场，联系维护者；不要继续记账 |
| 自检报"快照可重放 未通过" | 数据或代码被改动 | 同上；这是完整性告警，不是普通错误 |

重置口令：

```bash
python -m app.cli reset-password admin
```

## 十、试点前安全检查清单

- [ ] 管理员与经办人账号分开，口令均 ≥ 8 位且不相同
- [ ] 已设置 `protect-keys`（可选，但推荐）
- [ ] 已做一次**加密**备份，并验证过能在另一台电脑恢复
- [ ] 默认本机模式（未开 `--lan`），或已确认局域网范围与防火墙
- [ ] 已签署《数据处理协议》与农户告知同意书（见 PIA 文档）
- [ ] 已跑一次自检，全部通过
- [ ] 已确认没有人把 `data/keys/` 拷到个人设备
- [ ] 已向村委说明：报表可验证 ≠ 防造假

## 十一、交付清单

交给村委的东西应当是：

1. 程序目录（不含 `_scratch/`、`references/`、`.git/`）；
2. `启动.bat`；
3. 本手册 + 《操作指南》 打印版；
4. 一份加密备份（U 盘，单独上锁）；
5. 管理员口令（当面交接、当场修改）；
6. 联系人电话（写在本手册封面）。

不要交付：`_scratch/`（开发脚本）、`references/`（含个人信息的申报原件）、任何 `.key` 文件的副本。
