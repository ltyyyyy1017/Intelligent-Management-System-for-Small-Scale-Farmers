# 实现对照表（技术方案 V2 → 代码 / 测试 / 状态）

> 用途：评审时按节对照，答辩时"说到哪、指到哪"；接手的人先看这张表再读代码。
> 状态标记：**【已验证】** 有实现且被自动化测试覆盖 ｜ **【部分】** 有实现但有明确边界 ｜ **【未做】** 明确不做或依赖外部条件

---

## 一、总览

| 项 | 数值 |
|---|---|
| 交付形态 | 本地 Web 应用（标准库，零第三方依赖） |
| 代码规模 | `core/` 约 1 970 行；`app/` 约 5 870 行（含模板、CSS、SQL）；测试约 1 450 行 |
| 自动化测试 | **159 项**，全绿（`python -m unittest discover -s . -p "test_*.py" -t .`） |
| 数据库 | SQLite（WAL），17 张表 |
| 密码学 | SM3 / SM4-GCM / SM2，纯标准库实现 |
| 外部依赖 | **无**（不需要 pip install） |

## 三、数据库表

| 表 | 作用 |
|---|---|
| `village` | 村、区域、绑定的规则/参数版本 |
| `farmer` | 农户；姓名为 SM4-GCM 密文，对外用 `token` |
| `plot` | 地块（面积/权属/作物） |
| `machinery_use` | 农机年度作业量（折旧依据） |
| `event` | **核心事实表**，只增不改 |
| `evidence` | 凭证哈希与密文路径 |
| `rule_pack` / `param_pack` | 版本化规则与参数 |
| `snapshot` | 快照（自带输入、输出、签名） |
| `report` | 导出记录 |
| `audit_log` | 哈希链 |
| `token_map` | 代币映射（预留） |
| `user` / `session` | 账号与会话 |
| `outbound` | 受控外发记录 |
| `counter` / `meta` | 序列与元信息 |
