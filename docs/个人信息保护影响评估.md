# 个人信息保护影响评估（PIA）

> 依据：《个人信息保护法》第 55、56 条；《数据安全法》分类分级要求；商用密码应用要求。
> 评估对象：中小农户智能财务管理系统 V2（本地部署形态）。
> 评估时点：试点部署前。**本文档需由村集体与项目团队共同确认后留档**；本仓库版本是模板与初评，不替代外部法务意见。

---

## 一、评估结论（先给结论）

| 项 | 结论 |
|---|---|
| 是否处理敏感个人信息 | 是：身份证号、银行卡号、手机号、真实姓名（**设计中不采集身份证/银行卡原件图像**） |
| 是否向境外提供 | 否 |
| 是否自动化决策 | 否（不做征信评分、不做放贷决策） |
| 主要风险 | ① 设备被物理接触；② 外发时的组合泄露；③ 村委内部越权查看 |
| 风险等级（处置前） | 中 |
| 风险等级（处置后） | 低—中（残余风险可接受，需持续运维） |
| 是否可上线试点 | 在完成第九节措施、签署数据处理协议与告知同意书后，可试点 |

---

## 二、处理目的与必要性

| 目的 | 必要性 | 最小化措施 |
|---|---|---|
| 为农户核算经营成本与收益 | 核心功能，必须 | 只需要金额、科目、日期、地块面积；不需要消费明细 |
| 生成银行/补贴申报材料 | 核心功能，必须 | 只输出 L2/L3；L1 不进模板 |
| 村委代办记账 | 现实需要（老龄化） | 按账号分权，操作全部留痕 |
| 系统运维与故障排查 | 必要 | 只看运行日志，不看账目内容 |

**明确不做的处理**：不做征信评分、不做放贷决策、不做消费行为分析、不做跨村数据集中、不向第三方出售数据。

## 三、数据流

```text
[农户口述/纸质票据/表格]
        │  （本地录入，不联网）
        ▼
┌──────────────────────────────┐
│ 村委办公电脑（本系统）        │
│                              │
│  ① 录入 → 事件表（金额整数分）│
│  ② 凭证文件 → SM4-GCM 加密   │
│  ③ 姓名/手机号 → SM4-GCM 加密│
│  ④ 核算（纯函数，不出网）     │
│  ⑤ 报表渲染（只取 L2/L3）     │
│  ⑥ 快照 + SM2 签章           │
└──────────────────────────────┘
        │ 用户主动发起 + 勾选同意
        ▼
   ┌─────────────┐
   │ 银行/农经站 │  只收到：报表 + 快照 + 公钥
   └─────────────┘
```

**关键点**：不存在"系统自动上传"。任何出村动作都由人发起，且经过白名单、复检、确认、留痕四道闸。

## 四、个人信息清单与分级

| 级别 | 字段 | 来源 | 存储 | 界面显示 | 能否外发 |
|---|---|---|---|---|---|
| L1 | 真实姓名 | 村委建档 | SM4-GCM 密文 | 掩码（张*） | **禁止** |
| L1 | 手机号 | 村委建档 | SM4-GCM 密文 | 掩码（138****8000） | **禁止** |
| L1 | 身份证号 | **不主动采集**；若农户在备注里写了，扫描时会被掩码/阻断 | — | — | **禁止** |
| L1 | 银行卡号 | **不主动采集**；同上 | — | — | **禁止** |
| L1 | 精确住址/地块坐标 | **不采集**（只到村组） | — | — | **禁止** |
| L2 | 村组、地块面积、作物结构、交易对手 | 录入 | 明文（本地） | 可见 | 按必要性保留/泛化/代币化 |
| L2 | 农户代币（F-XXXXXXXXXX） | 系统生成 | 明文 | 可见 | 允许 |
| L3 | 收入、成本、净收益、亩产、保本价、成本结构 | 核算派生 | 明文 | 可见 | 允许（最小必要） |

**设计上的关键差异**：L1 不是"脱敏后可以发"，而是**数据模型里没有通往报表模板的路径**。
报表渲染器只接受 L2/L3 字段；即使有人改了代码想加姓名，也要先改白名单并留下审计记录。

## 五、合法性基础与告知同意

| 环节 | 合法性基础 | 落地动作 |
|---|---|---|
| 记账与核算 | 履行合同/服务所必需（农户委托村委代办） | 与农户签《服务委托与数据处理告知书》 |
| 姓名/手机号收集 | 单独同意 | 告知书上单独勾选，不默认勾选 |
| 向银行提供材料 | 单独同意 + 逐次同意 | 系统内"我同意"勾选 + 外发记录 |
| 向农经站提供汇总 | 单独同意 | 匿名化汇总，不含户级明细 |

**告知书要写清楚的六件事**：谁处理、处理什么、为什么、存在哪、给谁看、怎么删。

## 六、存储与安全措施

| 措施 | 实现 |
|---|---|
| 加密存储 | 凭证文件、姓名、手机号：SM4-GCM（AEAD，防篡改） |
| 密钥管理 | KEK/DEK 两级；设备密钥文件（可选口令保护，scrypt 派生） |
| 传输 | 默认不出网；本机回环 HTTP；局域网模式仅限村内网 |
| 完整性 | 事件集 SM3 哈希 + Merkle 根 + 审计哈希链 |
| 责任绑定 | 快照 SM2 签章（村委密钥 + 设备标识） |
| 访问控制 | 账号 + 口令（scrypt）+ 角色（admin/clerk/viewer）+ 会话 12 小时过期 |
| 防攻击 | CSRF 令牌、登录失败限速（5 次锁 5 分钟）、CSP/X-Frame-Options |
| 备份 | 一致性备份，可选口令加密；含密钥，需上锁保管 |

**诚实的边界**：能物理接触电脑并拿到整个 `data/` 目录（含 `keys/`）的人，可以解密数据。
这一层防的是"拷走数据库文件"和"U 盘丢失"，不是防"坐在电脑前的人"。
需要更强保护时启用 `protect-keys`，并把口令与设备分开保管。

## 七、对外提供（外发）

```text
用户发起 → 白名单取字段（L2/L3）→ 渲染材料包
        → 解压后逐成员扫描 L1 → 命中则阻断并审计
        → 用户勾选同意 → 打包 → 记录（谁/何时/给谁/哪些字段）→ 审计链
```

- 外发记录保存在 `outbound` 表，可在「隐私」页查看；
- 阻断事件同样入审计链，事后可追；
- 抽验原始凭证是**人工、单笔、经农户授权**的动作，不是系统自动披露。

---

## 八、保留期限与删除

| 数据 | 保留期 | 到期处理 |
|---|---|---|
| 账本与报表 | 按村集体财务档案要求（建议 ≥10 年） | 归档，不删除 |
| 凭证照片 | 与对应账目同期 | 同上 |
| 审计日志 | 长期 | 只增不删（删除会被校验发现） |
| 会话 | 12 小时 | 自动失效 |
| 语音（若将来接入） | 默认 30 天 | 自动删除（当前未接入） |

农户要求删除时：法律要求保留的财务档案不能删，但可以做**去标识化**（姓名/手机号置空、农户代币轮换），并记录处理过程。

## 九、风险与处置

| # | 风险 | 可能性 | 影响 | 处置 | 残余 |
|---|---|---|---|---|---|
| R1 | 电脑被偷/硬盘被拷 | 中 | 高 | 凭证与敏感字段加密；建议 `protect-keys` | 中 |
| R2 | 外发材料组合泄露（村名+面积+唯一作物） | 中 | 中 | 白名单 + 打包后复检 + 人工确认 | 低 |
| R3 | 村委内部越权查看 | 中 | 中 | 角色分权 + 审计留痕 + 姓名掩码 | 低 |
| R4 | 农户在备注里写了身份证/银行卡 | 中 | 高 | 录入时扫描并掩码；外发复检阻断 | 低 |
| R5 | 备份 U 盘丢失 | 中 | 高 | 备份口令加密 + 上锁保管 | 中 |
| R6 | 设备密钥泄露 | 低 | 高 | 密钥文件权限 600；口令保护；泄露即轮换 | 中 |
| R7 | 系统被植入后门 | 低 | 高 | 绿色部署、无网络、每次升级核对哈希 | 低 |
| R8 | 数据主体不知情 | 中 | 中 | 告知书 + 村内公示 + 语音版说明 | 低 |

## 十、数据主体权利

| 权利 | 实现方式 |
|---|---|
| 知情权 | 告知书、村内公示、系统内「隐私」页 |
| 查阅/复制 | 农户可要求打印自己的账本与报表（本人授权，村委经办） |
| 更正 | 通过"作废 + 重记"更正，保留原记录 |
| 删除/去标识化 | 见第八节；财务档案依法保留的部分做去标识化 |
| 撤回同意 | 可停止外发；已提供的材料由接收方按其规定处理 |
| 解释说明 | 报表每个数字可追溯到事件与规则版本 |

## 十一、角色与责任

| 角色 | 身份 | 责任 |
|---|---|---|
| 村集体 | **个人信息处理者** | 决定处理目的与方式；取得同意；保管设备与密钥；响应农户请求 |
| 项目团队（暨南大学） | **受托技术提供方** | 只提供软件与技术支持；**不接触生产数据**；不远程接入 |
| 银行/农经站 | 独立处理者 | 按自身合规要求处理收到的材料 |

双方须签署《数据处理协议》，明确：处理范围、安全措施、事件通报、终止后的数据处置、禁止再委托。

## 十二、安全事件响应

1. **发现**（自检告警、审计链断裂、凭证哈希不符、设备丢失）；
2. **止损**：停服务、断网、保留现场、备份当前状态（不要"修复"后再看）；
3. **评估**：涉及哪些农户、哪些字段、是否已外发；
4. **通报**：24 小时内报村委负责人；涉及敏感信息泄露的，按法律要求通知个人与监管部门；
5. **整改**：轮换密钥、重置账号、修补流程，并在审计链留痕；
6. **复盘**：更新本 PIA 与风险登记册。
