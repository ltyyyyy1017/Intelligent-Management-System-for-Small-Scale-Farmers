## 二、技术性错误（🔴 必须改）

### 1. Mask-BERT 被当作文字识别模型

| 项 | 内容 |
|---|---|
| 原文 | "系统内置深度学习大模型，能够自动识别农户的记账笔记和农机日志"（DOCX）；"Mask-BERT 模型训练"（PDF 实践过程）；"持续优化 Mask-BERT 模型性能，通过对比学习与锚样本策略提升模型对长尾类别和细粒度分类的区分能力"（DOCX 研究内容）；"基于 MASK-BERT 的文本识别"（DOCX 技术可行性） |
| 问题 | Mask-BERT 是**中文掩码语言模型**（知识增强 BERT），只处理文本、不处理图像，无法"识别手写记账笔记"。把 BERT 类模型写成 OCR，是评委最容易一击命中的点。另外"长尾类别/细粒度分类"与业务目标（金额、日期、类别对不对）不匹配 |
| 改法 | 拆成三层并各用对模型：OCR 用 PP-OCR 系列（检测+识别+方向）、版面分析用轻量版面模型、字段抽取用规则模板 + 小型 LLM（Qwen 级 INT4）或 GLiNER 零样本 NER。详细见 `技术方案V2.md` §7.1 |
| 话术 | "文字识别用 OCR 模型，语义抽取用小模型，BERT 类模型在我们方案里不承担识别职责" |

### 2. "隐私计算"术语误用

| 项 | 内容 |
|---|---|
| 原文 | "隐私计算模块负责本地敏感信息识别与脱敏处理"（DOCX 架构）；"采用隐私计算技术保护敏感信息"（PDF） |
| 问题 | 学界/业界"隐私计算"特指安全多方计算（MPC）、联邦学习（FL）、可信执行环境（TEE）、差分隐私等**在不可信参与方之间联合计算**的技术。本项目做的是"本地识别 + 脱敏 + 本地存储"，属于**数据脱敏与访问控制**，不是隐私计算。评委若来自安全领域会直接指出 |
| 改法 | 表述改为"本地数据脱敏与最小必要外发控制"；若确实要用隐私计算，只在"未来多村联邦汇总"（V3）场景提及联邦学习，并说明那是规划 |

### 3. "GCM 加密算法"与"SM4 国密"混用

| 项 | 内容 |
|---|---|
| 原文 | "采用 GCM 加密算法保护数据安全，密钥管理遵循'分级授权'原则"（DOCX 2.4）；"SM4 国密算法"（DOCX 技术可行性） |
| 问题 | GCM 是**分组密码的工作模式**（认证加密），不是算法；算法是 SM4/AES。写"GCM 加密算法"是概念错误。且两处分别提 SM4 与 GCM，没说清二者关系 |
| 改法 | 统一为"SM4-GCM（认证加密模式，同时保证机密性与完整性）+ SM3 摘要 + SM2 签名"，密钥分 KEK/DEK 两级，KDF 用 Argon2id。见 `技术方案V2.md` §8.4 |

### 4. "完全局域网不连公网" 与 "脱敏后上传云端" 自相矛盾

| 项 | 内容 |
|---|---|
| 原文 | "系统完全在村集体内部局域网（LAN）环境运行，不连接公网"（DOCX 2.2）；"脱敏后的数据上传至云端（节省本地存储压力），用于贷款申请、补贴审核等场景"（DOCX 2.3③）；"脱敏后安全上传至云端"（PDF） |
| 问题 | 同一份材料里既"不连公网"又"上传云端"，属硬矛盾。且"节省本地存储压力"这个理由不成立——农户账本数据量极小（一年几千条事件，几十 MB），根本不需要为此上云 |
| 改法 | 改为双模：**默认本地闭环、零外发**；外发是用户主动发起的受控动作（脱敏 → 复检 → 逐次确认 → 审计）。并删除"节省存储"这一理由，改为"向银行/补贴部门提交材料"。见 §8.2 |

### 5. 采集层超出部署条件（传感器 + 生长图像）

| 项 | 内容 |
|---|---|
| 原文 | "数据采集层：整合多源数据，包括传感器数据（土壤参数、环境参数、作物状态、设备状态）、农机日志…"；"收益预测模型结合作物类型、种植面积、生长图像、区域单产均值预测产量"（DOCX） |
| 问题 | 部署环境只有一台村委办公电脑、无外网、无田间设备。土壤/环境/设备传感器与作物生长图像从哪来？成本谁出？谁巡田拍照？这条链路在首版完全不成立。而"产量预测"被写成收益模型的核心输入，会让评审认为团队没想清落地条件 |
| 改法 | 首版删除传感器与图像，产量改为"面积 × 县域单产基准区间 × 历史自报系数"，并以**区间**输出；传感器与遥感移入 V3 路线图。见 §1.3、§6.5、§15 |

### 6. "深度学习大模型" + "i5/8GB 实时推理" 冲突

| 项 | 内容 |
|---|---|
| 原文 | "系统内置深度学习大模型…能在普遍的电脑上实时推理"（DOCX 研究目的） |
| 问题 | "大模型"通常指 7B 以上参数；在 i5/8GB 无独显机器上，7B 级模型无法做到"实时推理"。这一句会被追问"多大参数？什么量化？多少延迟？" |
| 改法 | 明确写"轻量化小模型（1.7B–3B，INT4 量化）+ 规则引擎"，给出模型体积、内存、延迟预算表；大模型只在开发期用于造测试数据，不进交付包。见 §7.4 |

## 三、不可验证断言（🔴/🟠）

| # | 原文 | 问题 | 改法 |
|---|---|---|---|
| 1 | "已获农业农村部试点认可" | **最危险的一条**。部级认可需有文件/回函，学生项目不可能有；一旦被要求出示即崩盘，且涉嫌虚假陈述 | 删除。若确有村/合作社试点意向，写"已与 X 村达成试点意向（附意向书）" |
| 2 | "创新的'隐性成本显式化'核算范式与端侧轻量化 AI 模型**已通过农村试点验证**" | 与"乙类：未创业"、与材料中"试点部署"仍在计划阶段的表述冲突 | 改为"完成实验室环境验证，试点验证列入 M6 里程碑" |
| 3 | "预计 3 年内覆盖超 50 万中小农户" | 50 万户需约 1 万个村的部署能力，与"6 人学生团队、单村部署"不匹配 | 改为"3 年内在 3 个县、30 个村完成部署，覆盖约 3000 户"（可执行、可验证） |
| 4 | "投资回报率（ROI）超 150%" | 未给成本项、周期、口径 | 给单村成本结构（设备复用 0、人力、培训、维护）与对照价值（材料代办市场价），算一个保守 ROI |
| 5 | "AI 分析准确率提升至 98% 以上" | "准确率"未定义（哪个任务？F1 还是准确率？测试集？）；98% 无来源 | 拆成 F2/F3/F4/F5 四项，各给测试集规模与目标值 |
| 6 | "推理效率提升 50% 以上" | 相对哪个基线？ | 改为绝对指标：端到端 P95 ≤ 3 s（可现场复现） |
| 7 | "审核效率提高 70%" | 谁的审核？怎么计时？ | 改为"银行尽调材料一次通过率"（试点期测量） |
| 8 | "帮助 65% 以上的中小农户实现规范化的财务管理" | 65% 的分母与统计口径不明 | 改为"试点村内 ≥ 60% 的常住农户在 3 个月内产生 ≥ 3 期完整账目" |
| 9 | "农户贷款成功率提高 30% 以上；补贴申请成功率提升 40% 以上" | 因果归因不成立：放贷决策受利率、抵押、政策、征信等影响，不是"有了报表就成功" | 改为过程指标："材料完整率 100%、补件次数 ≤ 1 次、审核往返时长缩短 X 天"（可测量、归因清晰） |

**通用规则**：凡出现"提升 X%""达 X% 以上"，必须同时给出三件事——① 测什么 ② 怎么测 ③ 现在是目标还是已达成。给不出，就换成过程指标。

## 七、答辩前的自查清单

按顺序过一遍，全打勾再交材料：

- [ ] 两份材料的项目名称、团队名单、年级、职称、领域完全一致
- [ ] 全文搜索"已获""已通过""已实现""领先""首创"，逐条确认能否出示证据，不能则改"目标"
- [ ] 全文搜索百分号，每个数字都能回答"测什么/怎么测/现在多少"
- [ ] 不再出现 Mask-BERT 承担识别、不再出现"隐私计算"指代本地脱敏
- [ ] 加密表述统一为 SM4-GCM / SM3 / SM2，不再出现"GCM 算法"
- [ ] 不再同时声称"完全离线"与"上传云端"，改为"默认离线 + 受控外发"
- [ ] 删除传感器与作物图像作为首版输入
- [ ] 空标题全部补内容（对比表、进度表）
- [ ] 角标 `[26]` 要么补文献要么删
- [ ] 规模断言改为可执行的村/户数量
- [ ] 现场能演示：一笔账跑出报表 + 重放数字一致 + 验签通过
